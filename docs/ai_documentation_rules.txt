AI DOCUMENTATION RULES
====================

1. DOCUMENTATION ACCESS RULES
--------------------------
1.1 Before Implementation
    - Always check project_documentation_index.txt first
    - Identify all relevant documentation files for the task
    - Read documentation in the following order:
        1. application_map.txt (for overall context)
        2. Relevant system documentation
        3. Component documentation
        4. Utility documentation

1.2 During Implementation
    - Keep documentation open and reference it frequently
    - Follow established patterns from documentation
    - Document any deviations from established patterns
    - Update documentation if new patterns are created

1.3 After Implementation
    - Verify implementation against documentation
    - Update documentation if changes were made
    - Document any new patterns or components
    - Check for consistency with other systems

2. DOCUMENTATION SEARCH RULES
--------------------------
2.1 Search Strategy
    - Use semantic search for finding relevant documentation
    - Search across all documentation files
    - Consider related systems and components
    - Look for similar patterns in other parts of the system

2.2 Context Awareness
    - Consider the broader system context
    - Look for dependencies between systems
    - Check for related components
    - Consider user interaction patterns

3. DOCUMENTATION UPDATE RULES
--------------------------
3.1 When to Update
    - When creating new components
    - When modifying existing patterns
    - When adding new features
    - When fixing bugs that affect patterns

3.2 How to Update
    - Maintain consistent formatting
    - Use clear and concise language
    - Include code examples where relevant
    - Document edge cases and limitations

4. IMPLEMENTATION RULES
--------------------
4.1 Component Creation
    - Follow patterns from common_components_system.txt
    - Use established naming conventions
    - Maintain consistent structure
    - Document new components

4.2 System Integration
    - Check for dependencies in application_map.txt
    - Follow established integration patterns
    - Consider performance implications
    - Document integration points
