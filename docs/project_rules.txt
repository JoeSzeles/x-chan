PROJECT RULES
============

1. DOCUMENTATION WORKFLOW
------------------------
1.1 New Feature Development
    ```cursor
    // 1. Check documentation index
    read_file("docs/project_documentation_index.txt", true, 1, 1)
    
    // 2. Search for related documentation
    codebase_search("feature name implementation", ["docs/"])
    
    // 3. Read relevant system documentation
    read_file("docs/related_system.txt", false, 1, 250)
    ```

1.2 Documentation Updates
    - Update documentation before implementing changes
    - Document new patterns immediately
    - Keep documentation in sync with code
    - Review documentation monthly

2. CODE ORGANIZATION
------------------
2.1 File Structure
    ```
    src/
    ├── components/
    │   ├── Common/         # Reusable components
    │   ├── Post/          # Post-related components
    │   ├── User/          # User-related components
    │   └── Layout/        # Layout components
    ├── services/
    │   ├── api/          # API services
    │   ├── auth/         # Authentication services
    │   └── storage/      # Storage services
    ├── models/           # Database models
    ├── controllers/      # Route controllers
    ├── utils/           # Utility functions
    └── docs/            # Documentation
    ```

2.2 Naming Conventions
    - Components: PascalCase (e.g., PostCard.jsx)
    - Services: camelCase (e.g., postService.js)
    - Models: PascalCase (e.g., PostModel.js)
    - Controllers: camelCase (e.g., postController.js)
    - Utils: camelCase (e.g., formatDate.js)
